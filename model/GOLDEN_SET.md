# Golden held-out evaluation set (`dataset_golden_v6`)

A fresh, oracle-verified, label-balanced v6 set that **nothing was trained or
previously evaluated on**, generated by
[`model/make_golden_set.py`](make_golden_set.py). Use it for a clean
base-vs-tuned-vs-hintfix number on data that is **provably disjoint** from every
existing split.

## What this is / why it's disjoint

Every record is built by the SAME verified pipeline as train/val/test/ood — no new
geometry and no new oracle:

```
problems.make_problem -> errors.inject -> dataset._partial_record
  -> dataset.finalize_record (dataset._assert_record oracle contract)
  -> v6_format.augment_record (re-derives + verifies the canonical net maps)
```

Records are two-step in-distribution problems (`errors.ID_COMPATIBLE_PATTERNS`),
balanced 20 per each of the 8 `transform_core.DIAGNOSIS_LABELS`, seed `20260712`
(distinct from `0` source, `20260709` eval sample, `20260711` v6 train/val).

**Canonical dedup key.** Disjointness is enforced on the pipeline's own key — the
observable geometry fingerprint

```python
json.dumps([original, correct_image, student_image], separators=(",", ":"))
```

RED pre-image + GREEN correct image + BLUE student image (the student image encodes
the injected error). This is the exact key used by
[`make_v6_transform_data._prepare_source_pools`](make_v6_transform_data.py) and the
leakage audit [`audit_v6_predictions.geometry_fingerprint`](audit_v6_predictions.py) —
problem geometry + injected error, NOT the numeric id.

Each candidate is rejected if its key collides with ANY record in:

- the frozen source `train / val / test / ood` (loaded in full), and
- v6 `train / val`, **reconstructed deterministically in memory** from seed `20260711`
  (the real `make_v6_transform_data._build_split`, no rendering), so the check is
  against the true cluster v6 geometry — plus any local v6 sample record files.

The generator asserts 0 overlap against every split and 0 oracle mismatches before
writing, and fails loudly otherwise.

### (a) Generate + render the golden set on the cluster

Deterministic and CPU-only (~30s incl. rendering); the login node is fine.

```bash
module load miniforge
conda activate slm 2>/dev/null || source activate slm
cd ~
# make_golden_set.py is code-synced to $HOME alongside make_v6_transform_data.py
python make_golden_set.py \
  --out-dir ~/transform_diagnosis_data_golden \
  --source-dir ~/transform_diagnosis_data \
  --seed 20260712 --n-per-label 20
python make_golden_set.py --verify \
  --out-dir ~/transform_diagnosis_data_golden \
  --source-dir ~/transform_diagnosis_data   # expect RESULT: PASS
```

Output dir `~/transform_diagnosis_data_golden/` contains `golden_v6.jsonl` +
`renders_v6/golden/` and is a complete `--data-dir` for the eval below.

> Alternative: since the local `dataset_golden_v6/` is byte-identical (deterministic)
> and already rendered, you may instead copy it up, e.g.
> `rsync -a dataset_golden_v6/ ikchen@orcd-login.mit.edu:~/transform_diagnosis_data_golden/`.

### (b) Evaluate base vs. original-tuned vs. hintfix on the golden split

`task=full`, both modalities, all 160 records (`--sample 0`). `eval_transform.py`
appends the split name, so tag `v6_4b_<modality>_<variant>` yields
`results_v6_4b_<modality>_<variant>_golden.json` (+ matching `records_...jsonl`).
GPU jobs (each is a short single-GPU run):

```bash
GOLD=~/transform_diagnosis_data_golden
COMMON='-p mit_normal_gpu -G 1 -c 8 --mem=64G -t 02:00:00'
PRE='module load miniforge; conda activate slm 2>/dev/null || source activate slm; cd ~;'

# ---- image-only arm ---------------------------------------------------------
sbatch -J g_img_base $COMMON -o g_img_base_%j.log --wrap "$PRE python eval_transform.py \
  --input image --task full --data-dir $GOLD --splits golden --sample 0 \
  --base-only --tag v6_4b_image_base"

sbatch -J g_img_tuned $COMMON -o g_img_tuned_%j.log --wrap "$PRE python eval_transform.py \
  --input image --task full --data-dir $GOLD --splits golden --sample 0 \
  --adapter ~/lora_adapters_v6_image --tag v6_4b_image_tuned"

sbatch -J g_img_hintfix $COMMON -o g_img_hintfix_%j.log --wrap "$PRE python eval_transform.py \
  --input image --task full --data-dir $GOLD --splits golden --sample 0 \
  --adapter ~/lora_adapters_v6_image_hintfix --tag v6_4b_image_hintfix"

# ---- image + coordinates arm ------------------------------------------------
sbatch -J g_crd_base $COMMON -o g_crd_base_%j.log --wrap "$PRE python eval_transform.py \
  --input image_coords --task full --data-dir $GOLD --splits golden --sample 0 \
  --base-only --tag v6_4b_image_coords_base"

sbatch -J g_crd_tuned $COMMON -o g_crd_tuned_%j.log --wrap "$PRE python eval_transform.py \
  --input image_coords --task full --data-dir $GOLD --splits golden --sample 0 \
  --adapter ~/lora_adapters_v6_coords --tag v6_4b_image_coords_tuned"

sbatch -J g_crd_hintfix $COMMON -o g_crd_hintfix_%j.log --wrap "$PRE python eval_transform.py \
  --input image_coords --task full --data-dir $GOLD --splits golden --sample 0 \
  --adapter ~/lora_adapters_v6_coords_hintfix --tag v6_4b_image_coords_hintfix"
```

Each writes `results_<tag>_golden.json` + `records_<tag>_golden.jsonl` to `$HOME`.
`--sample 0` evaluates all 160 golden records (deterministic, stable-sorted ids).

> The task text suggested `--tag v6_4b_image_coords_hintfix_golden`; because the
> split name is auto-appended that would produce `..._golden_golden.json`. The tags
> above keep the single `_golden` suffix and match the existing test/ood convention.

### (c) Read the 6-cell base-vs-tuned-vs-hintfix table (login node, no GPU)

```bash
cd ~
python - <<'PY'
import json, os
HOME = os.path.expanduser("~")
cells = [
    ("image",        "base"),    ("image",        "tuned"),    ("image",        "hintfix"),
    ("image_coords", "base"),    ("image_coords", "tuned"),    ("image_coords", "hintfix"),
]
hdr = f"{'cell':32s}{'both_nets':>10}{'correct':>9}{'student':>9}{'label':>8}{'derived':>9}{'hint':>7}"
print(hdr); print("-"*len(hdr))
for mod, variant in cells:
    tag = f"v6_4b_{mod}_{variant}"
    p = f"{HOME}/results_{tag}_golden.json"
    if not os.path.exists(p):
        print(f"{tag:32s}  (missing {os.path.basename(p)})"); continue
    a = json.load(open(p))
    def r(x): return "--" if a.get(x) is None else f"{a[x]:.3f}"
    print(f"{tag:32s}{r('both_nets_match_rate'):>10}{r('correct_net_match_rate'):>9}"
          f"{r('student_net_match_rate'):>9}{r('label_accuracy'):>8}"
          f"{r('derived_label_accuracy'):>9}{r('hint_match_rate'):>7}")
PY
```
